# Repair native JSON safety and typed map keys; scope compatibility claims

This PR repairs parser safety and native Serde correctness while keeping native and strict compatibility APIs separate. Native APIs use the project's parser and serializer. Both strict compatibility surfaces delegate directly to serde_json; the standalone `jzon-rs-compat` package pins `serde_json = "=1.0.151"`, preserves upstream public types and callbacks, and supports a separate alloc/no_std facade. It is a compatibility alias, with no independent acceleration or dependency-removal claim.

The safety repairs replace scanner-pointer depth guards with owned counters, explicitly validate container completion, and validate skipped string escapes and controls. Native characters use standard string visitors, serializer entry points accept `?Sized`, native writers stream through fallible sinks, and output/scratch buffers can be reused. Native readers remain buffered.

The local follow-up fixes the three remaining map-key findings: shared map access rejects nonquoted keys before invoking any key seed; boolean keys accept only complete quoted literal `true`/`false` tokens; both byte-key entry points delegate to native byte deserialization, preserving borrowed/transient callbacks and the pinned byte/surrogate model. Custom unit and unit-struct key visitors also consume quoted strings like the oracle. Eight native regression groups and a seeded typed differential fuzz target cover these paths through both `from_str` and `from_slice`. CI's Miri step includes the regressions, and the Fuzz matrix includes the typed target under both numeric policies.

Breaking API changes include removing the lifetime parameter from `DepthGuard`, clarifying scanner stats names, requiring an explicit call to disable recursion limits, and rejecting unsupported derive attributes that previously passed silently. Use the planned 0.4.0 breaking-change release strategy; this work does not publish a release.
